# packages/database

PostgreSQL schema and migrations. PostgreSQL is the authoritative record for tasks, budgets and
ledger state (spec §1, §5) — Redis is queue/cache only, never money truth.

Two migrations, applied in order, own different things (ADR-0004,
`docs/adr/0004-better-auth-for-identity.md`):

- **`migrations/0001_better_auth_schema.sql`** — identity (`user`, `session`, `account`,
  `verification`, `organization`, `member`, `invitation`). **Auto-generated by Better Auth's CLI,
  never hand-edited.** Regenerate it per the command in that file's header comment whenever
  `apps/api/src/auth.ts` or the `better-auth` version changes.
- **`migrations/0002_platform_tables.sql`** — everything else from spec §5 (`projects`,
  `agent_profiles`, `tasks`, `executions`, `usage_events`, `artifacts`, `verification_runs`,
  `payment_intents`, `audit_events`), hand-maintained. Its `organization_id`/`owner_user_id`
  foreign keys point at `0001`'s `"organization"`/`"user"` tables, so it must run second.

No ORM/migration framework has been chosen for `0002` (see PLAN.md §5 open decisions) — deliberately
framework-free plain SQL so that choice doesn't block Phase 1. `0001` is the one exception, since
its content isn't ours to author by hand.

Local dev: `docker compose -f ../../infrastructure/docker-compose.yml up -d postgres`, then apply
both files in order with `psql`. See `infrastructure/README.md` for the actual port (remapped from
Postgres' default to avoid colliding with other local containers on this machine).
